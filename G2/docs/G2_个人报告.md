# G2个人阶段报告

## 工作目标与职责

本模块负责交通灯实时系统的LLM生成实验执行、原始输出归档和初筛。以G1制定的单车道、单车需求为基准：绿灯20秒、黄灯3秒、红灯20秒，车辆1至5秒到达，2至3秒穿越。G5人工模型为理解需求和后续比较的参考，不作为生成输入提供给AI。

## 实验方法

使用G1的P0基础、P1时间自动机知识、P2安全约束提示词，每组采集5份。模型为GPT-6.1 Sol-中。不推测平台未公开的精确版本与采样参数。用户逐份或合并提交回复，由本聊天辅助机械提取、检查和整理。每份环境信息以metadata.md为准，不将未知信息补成事实。

三组任务范围相同，但P2更明确写出了穿越全程绿灯、剩余时间和占用保护。因此实验比较包含需求显式程度的影响，不能将差异全部解释成单一提示技巧的效果。

## 已完成操作

采集并编号15份模型，保留回复片段和完整回复；XML与查询分离保存，使用Python XML解析器检查根结构、模板初始位置和迁移引用。生成文件哈希，并将静态发现记录到各样本初筛说明。没有调用UPPAAL验证器，也没有制作模拟工具截图。


## 典型观察

P1-R01/R05允许绿灯接近20秒时进入，而车辆至少需2秒穿越。手工推演：车辆可在第1秒到达后等待，到第19秒进入，第20秒灯变黄时仍在Crossing。这是静态推导的反例路径，尚非UPPAAL生成的反例。

这两份的候选查询弱于小组安全要求：记录进入时为绿灯或允许黄灯状态，无法等同于穿越全程为绿灯。另有嵌套时序查询、未限定局部时钟引用的问题。由G7核对真实工具错误，不在本报告虚构编译输出。

P0部分样本采用紧迫握手，车辆在初始绿灯1至5秒到达后立即通行。这使模型不覆盖晚绿灯到达，不能仅因缺少剩余时间条件就断言当前范围一定不安全，也不能由当前安全推导任意到达场景安全。

P2五份均采用相位时钟<=17和路口占用保护，代码层面对安全要求的表达更一致。最晚17秒进入、最多3秒离开，且切灯等待释放占用。此为机制分析，尚不能写成P2形式化通过率100%。

## 学习与反思

XML可解析只说明文件结构能被读取。工具编译、模型行为和需求满足属于不同检查层次。guard规定允许迁移，不等于强制迁移；Waiting没有紧迫机制时可一直等待，存在完成路径不等于所有路径最终完成。评测应使用统一属性，不能用各AI自行生成的不同强度查询决定跨组优劣。
