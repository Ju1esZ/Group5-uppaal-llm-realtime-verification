## 已冻结的关键决策

1. 正常场景核心边界保持为单方向信号灯与单车通行；行人、对向车流和物理动力学不是基础实验的必做范围。
2. P0、P1、P2 每组进行 5 次独立生成，共 15 个原始样本；原始输出在首次评分前不得人工修复。
3. `v1` 是 G5 已完成的基础正常模型；`v2` 是吸收 G3/G4 审查和 G7/G8 验证结果后的正常场景整合版；`v3` 是 G6 的故障扩展版。
4. `raw` 表示 LLM 原始输出，不占用正式版本号，也不能被人工修订文件覆盖。
5. UPPAAL 的查询语言按官方支持的符号查询使用。时限响应通过观察者时钟/模板建模，不把通用 `within` 当成可直接使用的查询关键字。

## 推荐执行顺序

1. G2 使用 `prompts/` 中的冻结文本完成 15 次独立生成，并填写 `templates/实验运行记录.csv`。
2. G3/G4 对同一批原始样本独立审查，再合并错误分类，避免先看人工修复版。
3. G5 以已完成的 v1 为基线，根据真实错误证据形成 v2 候选，不覆盖 raw 文件和 v1。
4. G7/G8 按属性矩阵分别执行安全/活性和时限/统计工作，并保留失败轨迹。
5. G6 从通过正常场景验收的版本扩展 v3，记录故障注入和恢复语义。
6. G1 运行交付审计、组织评审并在版本登记表中记录结论。

## 快速检查

从仓库根目录运行：

```bash
bash G1/tools/audit_deliverables.sh
```

脚本只检查文件是否存在，并把未完成项标为 `MISSING`；它不等价于 UPPAAL 模型验证，也不会修改任何成员文件。

## G1 个人贡献表述

学习并梳理 UPPAAL 时间自动机模型架构、符号查询和实时属性分类；负责确定交通灯案例的需求边界、进程划分与需求追踪关系；设计基础、知识增强、安全约束三组 Prompt 对照实验及统一评价指标；建立 LLM 原始模型错误分类、运行记录和复核流程；定义 raw、v1、v2、v3 的版本演进与代码评审门槛；维护全组依赖、进度、风险和会议记录，并参与 Prompt 输出评审、模型调试、CTL/TCTL 风格属性验证与反例分析。
