# Prompt 对照实验方案

## 1. 实验目标

通过控制 Prompt 中形式化知识和安全约束的详细程度，比较 LLM 生成 UPPAAL 模型的可导入性、可编译性、可仿真性、形式化正确性和人工修复成本。

本实验不以“生成一个最好模型”为唯一目标，而是要求保留失败样本，以分析 LLM 在 XML、时间自动机、同步和查询生成上的典型错误。

## 2. 研究问题

- RQ1：加入 UPPAAL 结构和语法知识，是否提高 XML 导入率与模型编译率？
- RQ2：加入安全约束和自检要求，是否降低形式化语义错误和验证失败率？
- RQ3：Prompt 变详细后，错误是否从语法层转移到更隐蔽的时间语义或活性问题？
- RQ4：不同 Prompt 组的人工修复成本是否存在明显差异？

## 3. 实验组

| 组别 | 冻结文件 | 唯一主要增强量 | 预期观察 |
| --- | --- | --- | --- |
| P0 基础组 | `prompts/P0_基础Prompt.md` | 仅自然语言任务、参数和输出格式 | 作为无形式化知识提示的基线 |
| P1 知识增强组 | `prompts/P1_时间自动机知识Prompt.md` | 增加模板、时钟、不变量、卫士、复位、XML/查询语法提醒 | 观察结构/语法错误是否减少 |
| P2 安全约束组 | `prompts/P2_安全约束Prompt.md` | 在 P1 上增加安全、无死锁、剩余绿灯时间和自检清单 | 观察语义和验证通过率是否提高 |

三份 Prompt 已给出完整文本。正式实验开始后不得静默修改；如必须修改，复制为新版本并在版本登记表中说明原因，旧版仍保留。

## 4. 样本设计

- 每组独立生成 5 次，共 15 个 raw 样本。
- 样本编号固定为 `P0-R01` 至 `P0-R05`、`P1-R01` 至 `P1-R05`、`P2-R01` 至 `P2-R05`。
- 每次生成使用新会话，不提供前一轮输出、人工反馈或其他样本。
- 三组使用相同 LLM 产品、模型名称/版本、账户类型和生成日期窗口。
- 若 API 可设置采样参数，三组使用相同参数并记录；若界面不公开温度等参数，记录为 `N/A`，不得猜测。
- 每个样本只记录第一次完整回复。续写、修复或二次追问另存为 repair 样本，不计入 raw 首次通过率。
- 若模型拒答、截断或未返回 XML，也保留为有效失败样本，不能重新生成替代。

## 5. 原始材料保存规则

G2 建议按以下结构保存：

```text
G2/
├── prompts/                 # 从 G1 冻结版本复制并记录哈希/提交号
├── raw/
│   ├── P0/P0-R01/
│   │   ├── response.md      # 完整原始回复
│   │   ├── model.xml        # 仅机械提取，不修语法
│   │   ├── queries.q        # 仅机械提取，不修公式
│   │   └── metadata.md      # 模型、日期、参数、是否截断
│   ├── P1/
│   └── P2/
└── AI使用记录.md
```

“机械提取”只允许移除 Markdown 代码围栏，不允许补标签、改转义、改变量名或改查询。任何内容修复必须产生新文件，并关联原始样本。

## 6. 评测流水线

按顺序执行；前一阶段失败后，仍记录失败原因，后续阶段填写 `N/A`，不得把 `N/A` 当作通过。

| 阶段 | 检查内容 | 结果值 | 负责人 |
| --- | --- | --- | --- |
| S0 输出完整性 | 是否返回完整 XML 和查询，是否明显截断 | PASS/FAIL | G2 |
| S1 XML 解析 | 是否为良构 XML，是否含 `<nta>` 等必要结构 | PASS/FAIL | G2/G3 |
| S2 UPPAAL 导入/编译 | 工具是否接受声明、模板、系统实例和表达式 | PASS/FAIL | G3 |
| S3 结构审查 | 位置、边、初始位置、卫士、复位是否完整 | 错误数 | G3 |
| S4 并发审查 | 通道、共享变量、同步和死锁风险 | 错误数 | G4 |
| S5 仿真冒烟 | 是否存在正常灯循环和车辆完成轨迹 | PASS/FAIL | G3/G5 |
| S6 基线验证 | 统一基线查询是否可运行及满足 | 每条 SAT/UNSAT/ERROR | G7 |
| S7 时限验证 | 观察者构造和时限查询是否满足 | 每条 SAT/UNSAT/ERROR | G8 |
| S8 修复成本 | 从 raw 到可验收候选的修改量与用时 | 分钟/修改项 | G5/G6 |

## 7. 统一评价指标

设某实验组样本数为 `N=5`。

| 指标 | 计算方式 | 注意事项 |
| --- | --- | --- |
| 输出完整率 | S0 通过数 / N | 截断、拒答计失败 |
| XML 解析率 | S1 通过数 / N | 不能只统计“有 XML”的样本 |
| UPPAAL 编译率 | S2 通过数 / N | 以实际工具结果为准 |
| 仿真可运行率 | S5 通过数 / N | 必须观察到灯循环和车辆轨迹 |
| 基线查询可执行率 | 能运行全部统一查询的样本数 / N | 查询 ERROR 不算可执行通过 |
| 全部基线性质通过率 | 全部必选查询均 SAT 的样本数 / N | 与单条性质通过率分开报告 |
| 单样本错误密度 | 错误项总数 / 样本数 | 同一根因只计一次，连锁影响写备注 |
| 人工修复成功率 | 修复后达到候选验收的样本数 / 尝试修复样本数 | raw 指标不随修复结果改写 |
| 中位修复时间 | 每个样本修复分钟数的中位数 | 记录开始/结束和参与者 |

样本量较小，最终报告应同时给出原始计数（如 `3/5`）和百分比，不做过度统计推断。

## 8. 错误分类

| 编码 | 类别 | 典型例子 | 主审 |
| --- | --- | --- | --- |
| E1 | 输出/文件错误 | 回复截断、混入无法机械分离的说明、缺少 XML 主体 | G2 |
| E2 | XML/语法错误 | 标签不闭合、实体未转义、非法属性 | G3 |
| E3 | 声明/类型错误 | 未声明变量、类型不匹配、重复标识符 | G3 |
| E4 | 自动机结构错误 | 无初始位置、悬空边、不可达关键位置、遗漏状态 | G3 |
| E5 | 时间约束错误 | 不变量与出口矛盾、时钟未复位、上界导致死锁 | G3/G5 |
| E6 | 同步/并发错误 | 通道两端不匹配、共享状态竞争、错误同步导致死锁 | G4 |
| E7 | 需求语义错误 | 红灯通行、剩余绿灯不足仍进入、错误灯序 | G4/G7 |
| E8 | 查询错误 | 非法语法、实例名错误、性质与需求不一致 | G7/G8 |
| E9 | 活性/时限错误 | 存在无限等待、时限起点错误、观察者改变系统行为 | G7/G8 |
| E10 | 可追溯性错误 | 无法关联 Prompt、raw、修复版、查询和结果 | G1 |

严重度统一为：`BLOCKER`（无法继续工具检查）、`MAJOR`（可运行但违反核心需求）、`MINOR`（不影响核心结论但需修正）、`NOTE`（改进建议）。

## 9. 基线查询集合

用于跨 Prompt 比较的查询必须固定，不能采用每个 LLM 自己生成的查询作为唯一标准。最低集合：

```text
A[] not deadlock
A[] (VehicleProcess.Crossing imply signal == GREEN)
E<> VehicleProcess.Done
```

若 LLM 使用不同实例名，允许评测者只做“名称适配版”统一查询，但必须记录映射且不改变性质语义。名称适配后的结果与 raw 自带查询结果分栏统计。

活性和时限查询按 `03_CTL属性与验收矩阵.md` 执行；若模型没有必要观察变量，结果记为“不可表达/需插桩”，不能伪造通过。

## 10. 偏差控制

- G3 与 G4 先独立审查，再合并结论，减少互相暗示。
- 审查时优先隐藏 Prompt 组别；若文件名无法隐藏，在报告中声明未盲审。
- 统一使用同一 UPPAAL 版本和验证命令参数。
- 不删除失败样本，不以“最好的一次”代替 5 次总体结果。
- 不把 LLM 自己声称“已验证”当作证据；必须保存工具输出。
- 参数、查询或错误分类发生变化时，对三组样本同时重算。

## 11. 实验完成定义

以下条件全部满足后，G1 才能把 Prompt 对照实验标为完成：

1. 15 个编号均有原始回复和元数据，失败/截断样本也在其中。
2. 每个样本都有 S0-S8 的结果或有理由的 `N/A`。
3. G3/G4 的错误清单能回链到具体样本和证据。
4. G7/G8 保存统一查询、工具版本、结果和失败轨迹。
5. G8 汇总原始计数、比例、错误分布和修复成本。
6. G1 完成版本/评审记录，并在最终报告中披露样本量和实验限制。
