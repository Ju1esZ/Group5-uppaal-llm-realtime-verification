# 协作计划与进度看板

## 1. 全组交付链

```text
G1 需求/实验冻结
  -> G2 生成并保存 raw 样本
  -> G3/G4 独立审查后交叉复核
  -> G5 正常模型修复与 v2 整合
  -> G6 v3 故障扩展
  -> G7 安全/活性验证与反例
  -> G8 时限验证与统计汇总
  -> G1 版本验收、报告口径和最终复盘
```

任何下游工作都可以提前准备模板和查询，但不能伪造尚未收到的上游结果。

## 5. 会议机制

### 5.1 方案冻结会（M0）

- 确认 `WAIT_BOUND` 和起算点。
- 确认 v3 恢复策略和 `FAULT_TIMEOUT`。
- 确认 LLM 产品/模型、每组 5 次和生成窗口。
- 明确是否把多车/行人作为扩展而非必做。

### 5.2 数据检查会（M1/M2）

- G2 展示样本编号和缺失检查，不挑选“最好样本”。
- G3/G4 先分别汇报，再讨论分类冲突。
- G1 检查同一根因是否重复计数。

### 5.3 模型评审会（M3/M4）

- 作者演示模型变化和自测。
- G7/G8 展示失败属性和轨迹，不只展示通过项。
- 决定是否接受失败性质、修改需求或继续修模，并留下记录。

### 5.4 最终复盘会（M5/M6）

- 核对图表能否从 CSV 原始数据复算。
- 核对报告中的“存在”“所有”“最终”“时限内”等量词。
- 核对每位成员贡献与 Git/文件证据一致。

## 7. 风险登记

| 风险 | 影响 | 预防/处理 | 所有者 |
| --- | --- | --- | --- |
| raw 样本被覆盖或提前修复 | 实验不可追溯 | 只读保留 raw，修复另建文件 | G2/G1 |
| 不同 Prompt 使用不同模型/参数 | 对照失效 | 冻结环境并记录 N/A 参数 | G2 |
| 把 XML 可导入当作模型正确 | 错误结论 | 分阶段指标和统一查询 | G3/G7 |
| v2 定义缺失造成直接跳到 v3 | 正常/故障变化混杂 | v2 定义为正常整合版 | G1/G5 |
| 活性查询因无限拖延失败 | 报告误写或临时改性质 | 保留反例，讨论紧迫/公平设计 | G7/G1 |
| 观察者改变原模型行为 | 时限结果无效 | 评审同步和 urgent/committed 使用 | G8/G4 |
| 只报告通过项 | 形成选择性偏差 | 完整查询表，UNSAT/ERROR 均保留 | G1/G7/G8 |
| 样本量小却作强统计结论 | 结论过度 | 报原始计数、比例和限制 | G8/G1 |

## 8. G1 每次检查清单

- 上游材料是否齐全且未被后续版本覆盖。
- 需求、模型、查询和结果是否使用同一参数与版本。
- 每个结论能否回链到文件、提交号和工具输出。
- 失败项是否有责任人、处理决定和复验结果。
- 当前进度表是否反映真实证据，而不是口头完成状态。
- 跨目录修改是否通知对应主责并经过评审。
