# G5：基础交通灯模型 v1

## 交付内容

- `traffic_light_v1.xml`：可供 UPPAAL 导入的 XML 模型，包含信号灯控制器和单车进程。
- `queries.q`：G5 的基础无死锁查询及两条辅助性质。
- `UPPAAL_验证结果.txt`：UPPAAL 5.0.0 Verifier 的实际查询结果及完成通行见证轨迹。

## 模型边界

模型抽象为一个方向的交通灯和一辆车。控制器按绿灯 20 秒、黄灯 3 秒、红灯 20 秒循环；车辆经历 `Approach → Waiting → Crossing → Done`。时间单位为秒。模型不包含对向车流、行人、故障状态、感应器或物理车辆动力学；这些不属于 G5 基础模型范围。

| 模板 | 位置 | 含义 |
| --- | --- | --- |
| `TrafficLight` | `Green` | 绿灯阶段，阶段时钟不超过 20 秒 |
| `TrafficLight` | `Yellow` | 黄灯阶段，阶段时钟不超过 3 秒 |
| `TrafficLight` | `Red` | 红灯阶段，阶段时钟不超过 20 秒 |
| `Vehicle` | `Approach` | 车辆到达路口前，等待 1–5 秒 |
| `Vehicle` | `Waiting` | 等待满足绿灯通行条件 |
| `Vehicle` | `Crossing` | 正在通过路口，持续 2–3 秒 |
| `Vehicle` | `Done` | 本次通行已完成 |

控制器转换为 `Green → Yellow → Red → Green`；每次相位转换都在边上复位 `phaseClock` 并更新共享信号值。车辆转换为 `Approach → Waiting → Crossing → Done`；只有 `Waiting → Crossing` 依赖信号灯状态。

## 时钟、不变量和卫士

| 时钟 | 位置不变量 | 离开卫士 | 目的 |
| --- | --- | --- | --- |
| `phaseClock` | 绿灯 `<= 20`，黄灯 `<= 3`，红灯 `<= 20` | 对应阶段 `>=` 其持续时间 | 上界阻止时钟越界；达到边界时相位转换可执行，并在边切换时复位 |
| `arrivalClock` | `Approach` 中 `<= 5` | `>= 1` | 把车辆到达时间限制在 1–5 秒 |
| `crossingClock` | `Crossing` 中 `<= 3` | `>= 2` | 把路口通行时间限制在 2–3 秒 |

车辆只有在 `signal == GREEN` 且 `phaseClock <= 17` 时才可进入 `Crossing`。17 秒来自绿灯 20 秒减去最大通行时间 3 秒。车辆进入路口时将 `crossingOccupied` 置为真；控制器只有在该标志为假时才可离开绿灯。因此，路口内的车辆不会遇到信号灯提前切换。

| 模板 | 源位置 → 目标位置 | 卫士 | 更新 |
| --- | --- | --- | --- |
| `TrafficLight` | `Green → Yellow` | `phaseClock >= 20 && !crossingOccupied` | `phaseClock = 0, signal = YELLOW` |
| `TrafficLight` | `Yellow → Red` | `phaseClock >= 3` | `phaseClock = 0, signal = RED` |
| `TrafficLight` | `Red → Green` | `phaseClock >= 20` | `phaseClock = 0, signal = GREEN` |
| `Vehicle` | `Approach → Waiting` | `arrivalClock >= 1` | 无 |
| `Vehicle` | `Waiting → Crossing` | 绿灯且 `phaseClock <= 17` | `crossingOccupied = true, crossingClock = 0` |
| `Vehicle` | `Crossing → Done` | `crossingClock >= 2` | `crossingOccupied = false` |

## G5 验证目标

`queries.q` 中的查询为：

1. `A[] not deadlock`：所有可达状态均非死锁，是 G5 的基础验收属性。
2. `A[] (VehicleProcess.Crossing imply signal == GREEN)`：路口占用期间始终是绿灯。
3. `E<> VehicleProcess.Done`：至少存在一条可完成通行的路径。

按模型结构进行的静态检查结论：有时钟上界的位置都在边界上保留了可执行出口；绿灯出口受占用标志阻挡时，车辆在 `crossingClock == 3` 前必有完成边可走；无上界的等待和完成位置允许时间继续流逝。该结构推理随后由 UPPAAL Verifier 的实际检查确认。

## 运行与演示

在 UPPAAL 中打开 `traffic_light_v1.xml`，在 Verifier 页执行 `queries.q` 中的属性。也可在终端复现验证并输出最短见证轨迹：

```bash
verifyta -t 1 -y traffic_light_v1.xml queries.q
```

Verifier 为 `E<> VehicleProcess.Done` 生成的见证路径为：车辆从 `Approach` 进入 `Waiting`，在绿灯且剩余绿灯时间足够时进入 `Crossing`，通行至少 2 秒后进入 `Done`。这是 UPPAAL 引擎生成的符号轨迹；本记录不把它表述为 GUI Simulator 的人工录屏或逐步回放。
