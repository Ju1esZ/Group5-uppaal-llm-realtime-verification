# 基于 UPPAAL 的大模型生成实时系统模型形式化验证

本仓库用于整理课程小组作业成果：以交通灯控制系统为案例，比较大模型生成的 UPPAAL 实时系统模型，并通过人工审查、修正和模型检测评估其形式化正确性。

## 项目目标

- 建立车辆与信号灯协同运行的时间自动机模型。
- 记录大模型提示词、原始模型及人工检查发现的问题，区分语法问题与建模语义问题。
- 使用 UPPAAL 验证安全性、可达性、无死锁和时限性质，并记录反例或见证轨迹。
- 汇总不同提示词方案的模型可运行率、错误类别和验证结果。

目前仓库已收录 G5 的基础模型 v1、查询和验证记录。其他成员目录是分工与材料收集入口；未标为已完成的内容仍需对应成员补充，不能视为已有实验结果。

## G5 当前成果

G5 目录中的模型抽象为一个信号灯控制器和一辆车。信号灯采用绿灯 20 秒、黄灯 3 秒、红灯 20 秒的演示周期；车辆经历 `Approach → Waiting → Crossing → Done`。车辆只在绿灯剩余时间足够时进入路口，路口占用标志避免通行过程中信号灯提前切换。

在 UPPAAL 5.0.0 中已运行以下查询，三条均满足：

- `A[] not deadlock`
- `A[] (VehicleProcess.Crossing imply signal == GREEN)`
- `E<> VehicleProcess.Done`

模型假设、时钟不变量和卫士说明见 [G5 模型说明与验证记录](G5/G5_模型说明与验证记录.md)，Verifier 输出见 [G5 验证结果](G5/UPPAAL_验证结果.txt)。这些性质只说明当前抽象模型的检查结果，不代表实际道路安全结论。

### G5 复现验证

安装 UPPAAL 5.0.0 后，在 `G5/` 目录运行：

```bash
verifyta -t 1 -y traffic_light_v1.xml queries.q
```

模型结构和验证范围详见 [G5/README.md](G5/README.md)。
